# 3jsBridge 桥梁教学交互技术方案与项目管理规范

> 版本：v0.1 · 编制日期：2026-10-11 · 适用项目：[wonderbench/3jsBridge](https://github.com/wonderbench/3jsBridge)
>
> 已明确的项目主线：通过 Three.js 辅助桥梁相关知识的教学与认知。本文给出建议架构、开发注意事项和项目管理方式；所列功能、目录、性能预算和周期是待细化的方案，不代表已经实现或全部确认的需求。

## 1 项目定位与总体建议

建议把 3jsBridge 做成一个**可操作的桥梁知识教学工具**：学习者能旋转观察桥梁、认识构件、分步查看结构关系和建造过程，并通过讲解与交互理解知识点。画面效果服务于学习目标，优先解决“看哪里、这是什么、为什么这样、与其他桥型有何不同”。

默认采用 **React + TypeScript + Vite + Three.js + React Three Fiber（R3F）+ 按需 drei**，以“课程内容配置 + 桥梁语义模型 + 通用三维查看器”组织项目。第一版只做一个前端应用，无须为了教学展示预先引入后端、账号或学生数据分析。

### 1.1 建议教学范围

| 优先级 | 教学能力 | 学习者可完成的任务 |
| --- | --- | --- |
| P0 建议首版 | 一座示例桥、构件点选与讲解、构件树、预设视角、分步引导、显隐/隔离、恢复初始状态 | 找到主要构件，说明名称与基本作用，从整体切换到局部观察 |
| P0 选一个主题做深 | 构件拆解、结构剖面或施工顺序中的一个演示 | 按步骤解释构件关系或建造先后，而不是只播放动画 |
| P1 按课程需求扩展 | 梁桥/拱桥/斜拉桥/悬索桥对比、热点、概念性受力路径、简单理解检查、教师演示模式 | 比较差异，回答与本课目标相关的问题，并获得解释反馈 |
| 暂不默认建设 | 用户账号、成绩系统、学习行为上报、多人协作、GIS 大场景、复杂 BIM 管理 | 只有出现明确教学或运营需求时另行评估 |

构件名称、桥型差异、施工阶段和受力路径由桥梁知识审校人确认。受力箭头、变形夸张或运动演示可用于概念说明，界面标注“示意”及简化条件；工程性计算与结构安全判断不属于本项目主线，也不列为默认扩展方向。

### 1.2 首版教学闭环

建议选择一个可在短时讲解中完成的主题，例如“认识梁桥的主要构件”：

1. **给出目标。** 告诉学习者本节需要认出哪些构件、理解什么关系。
2. **整体观察。** 允许旋转、缩放，并随时回到推荐视角。
3. **引导认知。** 按步骤聚焦桥面、主梁、桥墩等相关构件，显示简短讲解。
4. **主动操作。** 点选、隔离或拆解目标构件，让学习者看到原本被遮挡的关系。
5. **解释与回顾。** 展示关键结论；需要时增加一题“找构件”或概念判断，反馈解释原因。

首版课程不应同时覆盖所有桥型。先验证一个主题的内容准确性和交互有效性，再复用架构制作更多课程。

### 1.3 开工前需要明确的输入

- 面向什么学习者，已有多少桥梁知识？主要用于教师讲解、自主学习，还是两者兼顾？
- 第一课的学习目标、桥型和必须讲清的知识点是什么？谁负责内容审校？
- 是否已有可使用的模型、教材或图示？格式、授权、精度和体积如何？
- 主要使用桌面、平板还是手机？浏览器、投屏、弱网或离线有什么要求？

没有现成模型时，先用程序化示例桥验证教学流程；不要等复杂资产全部制作完成才开始验证。

### 1.4 本次基础骨架与后续方案

本次配套基础代码实现一个三步骤教学小样：程序化桥面与两个桥墩、稳定构件 ID、模型点选或按钮选择、文字讲解、步骤高亮、旋转缩放，以及学习状态和视角重置。三维不可用时保留文字学习入口。示意尺寸与构造经过简化，不作为正式桥梁课程的完整内容。

当前代码集中在 `src/app/App.tsx`、`src/domain/teaching.ts`、`src/demo/introCourse.ts`、`src/features/course-player/CoursePlayer.tsx` 和 `src/features/bridge-viewer/BridgeViewer.tsx`，并包含领域及应用测试。`Course`、`LessonStep`、`BridgeComponent` 和 `SceneIntent` 已建立最小类型；后文的完整内容契约、独立 Viewer/Demo 模块、GLB 管线、拆解/剖切、热点、题目、浏览器 E2E 与性能门禁仍属于后续建设。

配套工程采用 **Node.js ≥ 22.12.0 与 npm**，提交 `package-lock.json`。本地使用 `npm ci` 安装、`npm run dev` 开发；`npm run check` 串联 lint、类型检查、单元测试和生产构建，另有 `build`、`preview`、`typecheck`、`lint`、`test` 脚本。这个检查入口不包含真实浏览器交互、真机性能或正式教学审核，发布前仍需执行对应验收。

### 2.2 从源码中提取可复用做法

**Three.js 与 Editor：学习场景基础和编辑器结构。** 阅读 [InstancedMesh](https://github.com/mrdoob/three.js/blob/dev/src/objects/InstancedMesh.js)、[GLTFLoader](https://github.com/mrdoob/three.js/blob/dev/examples/jsm/loaders/GLTFLoader.js) 和 [Editor](https://github.com/mrdoob/three.js/tree/dev/editor)。Editor 中的命令、历史、选择和 UI 分离值得借鉴；课程、知识点和构件语义不应直接等同于 Three.js 场景 JSON。实例化可减少重复桥梁构件的绘制开销，但原生实例拾取仍遍历实例，不能把实例化等同于拾取问题已经解决。

**R3F 与 drei：学习状态边界，保留对成本的判断。** 阅读 R3F 的 [性能陷阱](https://r3f.docs.pmnd.rs/advanced/pitfalls) 和 [性能扩展](https://r3f.docs.pmnd.rs/advanced/scaling-performance)，将面板和选中状态留在 React，把逐帧运动留在渲染循环或 ref。对 drei 的 [Instances](https://github.com/pmndrs/drei/blob/master/src/core/Instances.tsx) 和 [Bvh](https://github.com/pmndrs/drei/blob/master/src/core/Bvh.tsx) 检查默认行为：实例更新可能持续每帧执行，BVH 构建不因用了组件就自动移入 Worker。静态桥梁构件应按实际更新频率配置。

**three-mesh-bvh：学习加速结构与数据正确性。** 阅读维护方 [README](https://github.com/gkjohnson/three-mesh-bvh/blob/master/README.md) 和 [Worker 实现](https://github.com/gkjohnson/three-mesh-bvh/blob/master/src/workers/GenerateMeshBVHWorker.js)。索引重排可能影响三角形到构件的映射，应保留映射或评估 indirect 模式；直接查询的坐标空间、变形后 refit / rebuild、Worker buffer 转移均需处理。并行 Worker 的环境条件要单独验证，保留普通 Worker 或主线程小模型路径。

**glTF Transform：学习可重复的资产构建。** 阅读 [functions](https://github.com/donmccurdy/glTF-Transform/tree/main/packages/functions/src) 和 [instance 转换](https://github.com/donmccurdy/glTF-Transform/blob/main/packages/functions/src/instance.ts)。把去重、裁剪、纹理和网格优化做成离线步骤，并检查优化后语义 ID、动画和测量是否保留。检索时的 instance 转换会跳过带动画的文档，因此不能假设一条优化命令适合所有拆解或施工演示动画。

**Rapier 与 That Open：只借用明确需要的能力。** 阅读 Rapier 的 [Physics](https://github.com/pmndrs/react-three-rapier/blob/main/packages/react-three-rapier/src/components/Physics.tsx) 学习时钟分离；具体 React / R3F / Rapier 版本必须成组验证。阅读 That Open 的 [FragmentsManager](https://github.com/ThatOpen/engine_components/blob/main/packages/core/src/fragments/FragmentsManager/index.ts) 和 [土木断面导航](https://github.com/ThatOpen/engine_components/blob/main/packages/front/src/civil/CivilCrossSectionNavigator/index.ts)，学习 BIM 数据与场景能力分开组织。这两项都不是教学 MVP 的默认依赖。其 Components 仓库为 MIT，但 `engine_web-ifc` 为 MPL-2.0；引入完整链路前核对实际依赖及分发义务。

### 2.3 建议学习产出

不以“看完仓库”作为完成标准。先做四个小实验，并把结论记录在技术试验 Issue：

1. 一个带稳定构件 ID 的小桥场景，完成点选、树联动、隐藏和重置。
2. 同一批重复构件对比普通 Mesh 与实例化，记录 draw call、帧耗时和拾取耗时。
3. 对同一资产做压缩前后对比，记录传输体积、解码时间、视觉差异与 ID 映射完整性。
4. 连续切换模型和拖动时间轴，检查状态重放、取消竞态和资源趋势。

这些是后续学习与技术验证任务，本文不宣称已完成本项目的安装、运行或性能测试。

## 3 技术路线与依赖治理

### 3.1 推荐技术组合

| 层次 | 建议选型 | 采用原因与边界 |
| --- | --- | --- |
| 应用与构建 | TypeScript 严格模式、React、Vite、npm | 管理讲解、课程导航、属性面板与三维联动；提交 package-lock.json |
| 三维场景 | Three.js、R3F、按需 drei | 复用声明式场景与控制器；几何和内容数据保持框架无关 |
| 状态管理 | React 局部状态，跨面板复杂时再引入 Zustand | 保存课程步骤、选中 ID、显隐和播放状态；不保存 GPU 对象 |
| 教学内容 | 版本化 JSON/TS 配置与运行时 Schema 校验 | 讲解与交互步骤可复用，外部内容在加载边界校验 |
| 教学资产 | 程序化几何或 GLB；按需 Meshopt/Draco、KTX2 | 先保证构件语义和教学可读性，再优化体积与加载 |
| 重处理 | 必要时 Web Worker | 用于大文件解析、索引等；小课程不必强行 Worker 化 |
| 质量保障 | ESLint、格式检查、TypeScript、Vitest、Playwright | 单测覆盖内容与状态逻辑，浏览器测试覆盖真实交互 |
| 发布 | 静态托管、版本化资产，可选 CDN | MVP 不依赖服务端；公开部署前核对资产授权 |

React 团队优先 R3F；如果团队已有其他前端栈或成熟 Three.js 引擎，可保留原生 Three.js 渲染层。二选一并记录 ADR，不让两个系统同时控制同一场景对象的生命周期。

MVP 优先验证 WebGLRenderer 路线；当前官方实现要求 WebGL 2，需检测支持情况并提供明确提示及可阅读的教学文字。WebGPU 是否引入取决于实际需求和目标设备；其后备机制不代表现有材质、插件和后处理可以免测试迁移。[官方渲染器文档](https://threejs.org/docs/pages/WebGLRenderer.html)

### 3.2 依赖与升级规则

1. 初始化时选择经过验证的 Three.js / R3F / drei 兼容组合，在 README 写明 Node 与包管理器版本；不要直接拼接各示例仓库的“最新版”。
2. 保持 Three.js 的实例来源一致，检查 peer dependency。CI 使用 `npm ci` 按锁文件安装，升级形成单独 PR 并回归课程。
3. 新增依赖说明用途、包体成本、维护状况、许可证及退出方式。Rapier、BVH、IFC 工具均为按需选择。
4. 代码与模型、贴图、字体、图片、音频授权分别登记；开源仓库的代码许可不自动覆盖所有演示资产。

## 4 教学应用架构

### 4.1 模块化单体与依赖方向

```text
教学界面 UI          课程目录  讲解卡片  构件树  工具栏  进度导航
       ↓ commands / selectors
应用层 Application   开始课程  切换步骤  选择构件  播放演示  重置
       ↓                          ↓
领域层 Domain                  接口 Ports
课程 知识点 步骤 构件 题目      CourseRepository  AssetRepository
                                 ProgressRepository 可选
       ↑ 转换或实现                ↑
内容与资产适配层              三维 Viewer 与 Demo Runtime
JSON GLB 本地配置             相机 拾取 高亮 剖切 拆解 时间轴
```

领域层不依赖 React、Three.js 或网络。应用层处理用例，Viewer 将领域状态映射为场景，内容适配器负责加载与校验，应用入口装配这些模块。消息可以双向流动，但不允许任意双向 import；用边界检查防止循环依赖。

典型流程：点选桥墩 → Viewer 转换命中对象为 `componentId` → 应用状态更新 → 构件树、高亮和讲解共同响应。课程切换步骤时发送明确的场景意图，而不是让讲解组件直接遍历 Mesh。

### 4.2 建议目录

```text
3jsBridge/
├─ src/
│  ├─ app/                # 启动、布局、依赖装配、错误边界
│  ├─ domain/             # 课程、步骤、构件、单位与纯逻辑
│  ├─ application/        # 用例、状态协调、端口
│  ├─ features/
│  │  ├─ course-player/   # 课程导航、步骤与讲解
│  │  ├─ bridge-viewer/   # 三维页面与工具编排
│  │  ├─ component-tree/  # 构件查找与层级
│  │  └─ knowledge-check/ # 可选的理解检查与解释反馈
│  ├─ viewer/             # 相机、拾取、材质、剖切、资源生命周期
│  ├─ demo/               # 教学动画、统一时钟、拆解和阶段状态
│  ├─ adapters/           # 内容与资产加载、可选本地保存
│  └─ shared/             # 小型通用 UI 与工具
├─ content/               # 课程配置、讲解、来源与审校信息
├─ public/assets/         # 可公开的小型样例与发布资产
├─ tests/                 # 内容、单元、集成、E2E 和性能夹具
├─ scripts/               # 资产转换与内容校验
├─ docs/                  # 方案、ADR、内容规范、测试与发布说明
└─ .github/               # 后续建立的模板、工作流及 CODEOWNERS
```

按真实功能逐步建立目录，不要求第一次提交铺满空文件夹。先打通一节课的完整流程；只有出现独立复用或发布需求时再拆 packages。

### 4.3 状态与资源边界

| 状态类别 | 归属 | 例子 |
| --- | --- | --- |
| 可序列化课程与业务状态 | 应用 store / 局部状态 | 当前课、步骤、选中 ID、显示模式、播放/暂停 |
| 三维运行时对象 | Viewer | Object3D、相机、纹理、控制器、拾取索引 |
| 高频动画数据 | Demo runtime / ref | 当前时间、插值、矩阵、临时向量 |

异步加载带 `requestId` 和内容/模型版本，切换课程后旧请求不能覆盖新课程。场景模块提供 `load`、`focus`、`setSelection`、`applyStep`、`reset`、`dispose` 等接口。重置必须恢复场景与教学步骤的约定状态，不能只复位相机。

本地保存学习位置可以作为便利功能，默认无须账号。跨设备同步、成绩管理或学习行为分析必须等明确需求后再设计；不默认收集身份、年龄、答题记录或其他学生信息。

## 5 课程内容与桥梁语义模型

### 5.1 内容契约

教学内容与三维资产分别维护，通过稳定 ID 关联。一个教学构件可对应多个 Mesh，重复构件也可使用实例化；显示名称、数组位置和运行时 UUID 都不适合作为业务主键。

| 数据 | 建议字段 | 校验重点 |
| --- | --- | --- |
| Course | `courseId`、版本、标题、适用对象、学习目标、前置知识、步骤、来源 | 学习目标可观察；讲解对应目标；引用与审校状态明确 |
| LessonStep | `stepId`、讲解、目标构件、场景意图、可选演示、完成条件 | 构件存在；可直接跳入；前进、后退与重置结果一致 |
| Component | `componentId`、类型、名称、层级、教学说明、`renderBindings` | ID 唯一；映射完整；名称和作用审校通过 |
| SceneIntent | 视角、目标点、显隐、隔离、高亮、剖切、拆解参数 | 不依赖上一段动画的残留状态；参数有合法范围 |
| Hotspot | `hotspotId`、构件绑定、锚点、标题、说明、可选替代文字 | 锚点不漂移；标签不过度遮挡；可从 DOM 入口访问 |
| KnowledgeCheck 可选 | 目标知识点、题型、题目、答案、解释 | 答错有解释；不考界面操作速度；不默认记录个人成绩 |
| AssetManifest | 模型版本、URL、哈希、单位、坐标、构件索引、授权 | 课程与模型版本兼容；资产来源可追溯 |

新增课程应主要新增内容与资产配置，而不是复制一套 Viewer。自定义交互由有限的类型化动作组成，不允许内容文件携带任意 JavaScript。

### 5.2 教学内容的编写与审核

每节课先写“学习者完成后能做什么”，再决定模型、视角和操作。讲解宜采用短段落，先说明观察对象，再提出问题，最后给解释；避免同时出现过多标签、动画和长篇文字。

示例目标可以是“在模型中指出主梁与桥墩，并用自己的话说明二者的基本作用”。对应验收应包含识别与解释，不能只记录“动画播放完毕”。涉及桥型比较时，应说明概括适用的范围，避免把示例桥的特征说成所有桥梁都具备。

内容流程建议为：教学设计 → 桥梁知识审校 → 三维映射与交互制作 → 教学走查 → 发布。保存内容版本、作者/审校角色、引用资料和修改说明。事实错误与技术缺陷一样进入 Issue，并可独立修订。

### 5.3 概念演示规则

- 受力箭头、颜色和形变用于解释关系时标明“概念示意”，说明省略或简化的因素；不显示没有来源的精确数值。
- 夸张变形与实际几何分开控制，必要时显示倍率或说明；复位后恢复原始状态。
- 施工顺序应注明是所选案例或教学简化，实际工程可能采用不同工法。
- 优先让学习者主动比较或操作，每段动画都对应一个明确问题；播放特效本身不是学习目标。

## 6 资产与坐标管线

### 6.1 先保证教学表达

优先使用可识别、可拆分、授权清晰的轻量模型。减少对知识点无帮助的细节，保留影响构件辨认的轮廓、层次和连接关系。可用不同材质辅助区分构件，但颜色不得成为唯一信息通道。

推荐流程：源文件与授权登记 → 构件语义 ID → 单位和坐标统一 → 几何/材质清理 → 教学分组与拆解轴检查 → 按需压缩/LOD → 视觉与映射校验 → 发布模型加 manifest。

### 6.2 坐标和资产约束

- 运行时建议右手系、米、Y 向上，桥轴沿 X；明确原点和源数据转换，导入边界只转换一次。[glTF 坐标与单位规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#coordinate-system-and-units)
- 建立已知方向和尺寸的小夹具，检查导入后相机、拆解、剖切、热点与拾取点一致。尺寸展示的精度以资产为依据。
- 优化或合并几何不得丢失构件 ID。保存源资产、转换工具版本、参数、输入输出哈希和授权记录。
- 压缩前后比较传输体积、解码时间、外观、热点及构件映射。网络文件变小不代表 GPU 内存同比下降。
- 大型源模型不直接放进普通 Git 历史；使用适用的资产存储或 LFS。公开仓库和预览环境只放可公开分发的资产。
- 图片、标签、字幕和讲解文本同样是课程资产，纳入版本与内容校验。

## 7 交互 动画与可访问性

### 7.1 交互规则

查看、选择、剖切和拆解共用明确的工具状态。点击与拖动区分，触摸取消有处理，面板遮罩优先于场景；根据 Canvas 实际边界计算指针坐标。R3F 的相交对象事件传播需有意控制，避免一次点击选择多个遮挡构件。[事件文档](https://r3f.docs.pmnd.rs/api/events)

悬停、高亮、选中是独立状态。构件树与场景通过 `componentId` 联动；隐藏对象不得在默认选择路径中抢占命中。热点数量与标签密度按视图控制，关键内容也应能通过列表访问。

引导相机可以被暂停或跳过；用户自由观察后可“一键回到讲解视角”。下一步、上一步、重新播放和重置均要有明确语义。课程快速切换或连续点击不能留下混合场景。

### 7.2 可重放的教学动画

使用一个统一时钟，显示状态尽量直接由步骤与时间 `t` 求值，避免持续累加位置。这样暂停、拖动、回看和跳转可得到一致结果。需要积分的少量演示才采用固定步长与插值，不为普通拆解动画引入物理引擎。

动画结束或课程暂停后恢复按需渲染；播放、相机阻尼等期间正确请求连续更新。每帧更新通过 runtime/ref，不以每帧 React setState 驱动几何变换。后台页恢复时控制过大的时间增量。

### 7.3 教学可访问性

- 为讲解、构件名称和主要操作提供 DOM 文本与键盘入口；不能把所有教学信息仅画在 Canvas 中。
- 支持暂停、减弱或跳过动画；避免强制连续相机运动。
- 用文字、形状或边框配合颜色区分状态；检查文本对比度、焦点顺序和按钮命名。
- 主要拖拽交互尽量提供按钮或预设值替代，手机端保证可点击面积，投屏场景检查字号。
- 三维能力不足或模型失败时仍保留课程说明、错误原因和重试入口，不出现只有空白画布的页面。

## 8 性能与资源生命周期

### 8.1 建立可复现基线

首轮试验固定课程、模型版本、构件数、面数、纹理体积、浏览器、GPU、分辨率、DPR 和网络条件。以下只是**待真实资产和目标设备校准的初始预算**，不是已达到的结果或对所有设备的承诺。

| 指标 | 初始候选目标 | 验证条件 |
| --- | --- | --- |
| 首个可操作教学视图 | ≤ 5 秒 | 冷缓存、20 Mbps / 50 ms RTT；多次运行记录中位数与长尾 |
| 演示帧耗时 | p95 ≤ 33.3 ms | 首批目标笔记本、1080p、DPR 上限 1.5；固定 60 秒观察路线 |
| 点选至反馈 | p95 ≤ 100 ms | 已加载场景中至少 100 次分布于不同构件的操作 |
| 首屏关键 3D 资产 | 暂以 ≤ 15 MB 预警 | 讲解第一步必需的资源总和；高清和后续课按需加载 |
| 稳态 draw call | 暂以 ≤ 200 预警 | 记录阴影、材质和后处理条件；超出后依据测量决策 |
| 课程加载与卸载 | 连续 20 次后资源趋势稳定 | 预热后观察资源计数和内存；不要求内部缓存绝对归零 |

移动端若列为目标，单独建立设备与降级档。CI 中软渲染的帧率不能冒充真机性能。

### 8.2 按实际瓶颈优化

| 问题 | 先观察 | 优先措施 |
| --- | --- | --- |
| 打开课程慢 | 网络、解码、主线程任务 | 轻量首屏、分步资源、压缩、缓存和取消机制 |
| 观察时掉帧 | draw call、像素填充、阴影与透明叠加 | 重复构件实例化、LOD、DPR 与特效质量档 |
| 悬停卡顿 | 拾取范围、频率和网格复杂度 | 限定可交互集合、节流、代理网格，必要时 BVH |
| UI 频繁重绘 | React 提交频率和订阅粒度 | 切分订阅，逐帧状态留在 runtime |
| 切课后越来越慢 | 请求、监听器、纹理和几何残留 | 取消旧任务、明确所有权、清理共享缓存 |

实例矩阵改变后维护更新标记和包围体；按空间分区实例，避免过大包围体影响剔除。BVH 对变形网格需要维护，不能直接套用静态索引。循环内复用临时向量和矩阵，避免逐帧创建大量对象。

### 8.3 释放与可靠性

退出课程时停止帧回调和定时器、取消请求、清理事件订阅、撤销临时 URL，并按资源所有权释放 Geometry、Material、Texture、RenderTarget、Controls 和后处理资源。场景中移除 Mesh 不等于释放 GPU 资源，释放 Material 也不自动释放纹理。[Three.js 资源清理](https://threejs.org/manual/pages/cleanup.html)

共享资产明确 owner 或引用计数；高亮不能意外修改所有共用材质的构件。检查快速切课、加载失败、窗口 resize、后台恢复和 WebGL context loss。R3F 的自动清理不能替代外部对象、自定义缓存和异步任务的生命周期设计。

## 9 测试 安全与发布

### 9.1 软件与教学双重验收

| 层次 | 必测内容 | 通过证据 |
| --- | --- | --- |
| 内容校验 | 课程 Schema、构件引用、步骤完整性、来源与审校状态 | 自动校验报告和内容审核记录 |
| 单元测试 | ID 映射、坐标转换、步骤求值、播放状态、重置 | 正常与边界输入的纯逻辑测试 |
| 集成测试 | 加载、取消、乱序响应、课程与 Viewer 同步、共享资源 | 小型正常/损坏模型夹具 |
| 浏览器 E2E | 开课、找构件、读讲解、切步骤、暂停、回看和重置 | 实际浏览器流程与异常检测 |
| 视觉与性能 | 固定视角、标签、色彩、拆解、重复切课和真机帧耗时 | 固定版本基线；合理容忍 GPU 视觉差异 |
| 教学走查 | 知识准确、讲解顺序清楚、操作帮助理解、避免误解 | 内容审校与代表性使用者反馈；不把播放完成等同于掌握 |
| 可访问性 | 键盘、焦点、减少动画、文字替代、窄屏与投屏 | 操作清单和问题修复记录 |

保留快速小夹具、真实规模基准课、故意损坏的异常资产。视觉测试固定相机、时间、随机种子、浏览器与视口；跨 GPU 不要求逐像素绝对一致。[Playwright 视觉快照](https://playwright.dev/docs/test-snapshots)

### 9.2 安全与隐私

- 外部模型和配置限制文件大小、纹理尺寸、解压后大小、处理时间和构件数量；解析可取消，错误可恢复。
- 限制模型外部 URI 的协议和来源；讲解与属性默认按文本显示，富文本需要清洗，禁止执行内容中的任意脚本。
- 密钥不进入前端、仓库或日志。公开发布前核对模型、教材摘录、图片与音频的授权范围。
- MVP 不要求收集学生身份或成绩；如以后确需采集，另行明确必要性、告知与授权、保留期限和访问控制。
- 部署按实际需求配置 CSP、CORS 和缓存策略；依赖更新和漏洞评估不能只看 Star。

### 9.3 CI 与发布流程

建议流水线为：可复现安装 → 格式/lint → TypeScript → 单元/契约测试 → 内容与资产校验 → 生产构建 → 小型课程 E2E → 依赖与许可证检查。真机性能及完整教学走查按变更范围或发布周期执行，并明确哪些是门禁。

开发、预览和生产配置分开；预览使用可以公开的样例。每个发布记录应用版本、Git commit、课程版本、资产清单哈希和 Schema 版本。静态资产使用内容哈希，入口与清单使用可更新缓存。

回滚同时恢复应用及兼容课程/资产清单，不能只回退 JavaScript。发布前检查旧链接、缓存、本地保存状态和已知限制。错误日志记录版本、加载阶段与资源 ID，避免默认采集个人学习内容。

## 10 项目管理架构

### 10.1 角色与责任

小团队可以一人多角，但每个交付物应有一个最终负责人；技术通过不能替代知识准确性审核。

| 角色 | 责任 | 核心交付物 |
| --- | --- | --- |
| 产品/项目负责人 | 用户对象、范围、优先级、节奏、验收及变更取舍 | 首版目标、里程碑、验收清单 |
| 教学内容负责人 | 学习目标、讲解顺序、活动与反馈设计 | 课程脚本、步骤和理解检查 |
| 桥梁知识审校人 | 构件术语、桥型知识、施工顺序、概念示意准确性 | 内容审核意见与误解风险说明 |
| 技术负责人 | 架构、接口、兼容组合、性能预算与跨模块风险 | ADR、数据契约和关键评审 |
| 三维/前端开发 | Viewer、教学 UI、交互、自动化测试、监测 | 可演示功能、测试和性能证据 |
| 模型/视觉负责人 | 资产语义、可辨识性、拆解、纹理与授权 | 模型、manifest 与转换记录 |
| 测试/发布负责人 | 兼容、可访问性、教学流程回归和版本发布 | 测试报告、发布及回滚记录 |

产品负责人决定范围与优先级，教学负责人定义学习活动，知识审校人确认内容，技术负责人决定实现路径。新增效果应回答“帮助哪个学习目标”，不能仅以画面更复杂作为排期依据。

### 10.2 WBS 与工作流

建议按以下工作包建立 Epic，再拆成可独立验收的 Issue：

1. **教学需求。** 学习对象、第一课主题、目标和验收任务。
2. **内容与模型。** 课程脚本、知识审校、语义 ID、授权和资产处理。
3. **基础工程。** 依赖、目录、数据契约、渲染小样和 CI。
4. **教学交互。** 点选、讲解、构件树、步骤、视角和重置。
5. **概念演示。** 选定的一项拆解/剖面/施工主题及可重放动画。
6. **质量与交付。** 性能、异常、设备兼容、可访问性、教学走查和发布。

关键路径是“目标与第一课脚本 → 模型及 ID 契约 → 一节课纵向闭环 → 教学与性能验证 → 发布”。内容与开发可以并行，但场景热点、拆解方向和讲解名称要共同验收。

看板建议 `Backlog → Ready → In progress → Review → Verify → Done`，另设 `Blocked` 并注明解除条件。Issue 至少包含目标、范围、负责人、依赖、输入样例、验收步骤、估算与风险；Ready 要求关键输入已明确，每人同时推进一项主要任务。

### 10.3 分支 评审与变更

- 采用受保护的 `main` 与短期功能分支；Issue、PR 和里程碑关联，不默认建立长期 `develop`。
- PR 围绕一个目的，附行为变化、截图/演示、测试、性能影响、内容/资产变化及回滚方式。
- 内容 PR 由教学或知识审校角色检查；核心接口、依赖、坐标、资源生命周期变化由技术责任人检查。
- 公共契约或关键选型变化记录 ADR：背景、备选、取舍、影响和复查条件。单人项目保留自查，但不把自查写成独立审核。
- 每周展示真实运行课程，复盘“是否更易理解”与技术问题。采用一至两周迭代时，先确定目标和输入，再承诺具体任务。
- 新需求说明对内容、模型、代码、测试和时间的影响，由负责人决定替换、延后或新增工作；避免首版同时铺开所有桥型。

后续应建立 `CONTRIBUTING.md`、Issue/PR 模板、`CODEOWNERS`、`docs/adr/`、内容规范、资产规范和发布清单。文档中的建议不代表仓库已经启用分支保护、门禁或自动部署。

## 11 里程碑 风险与完成标准

### 11.1 建议里程碑

以下是小型团队的规划起点，假设能及时获得内容审校与一套轻量资产；正式周期需经技术试验和第一课范围确认，不是交付承诺。

| 阶段 | 参考投入 | 主要产物 | 出口条件 |
| --- | --- | --- | --- |
| M0 教学与技术试验 | 2–3 个工作日 | 第一课脚本、样例桥、坐标/ID 契约、设备基线 | 学习目标可验收，资产可用，主要风险可解释 |
| M1 单课纵向闭环 | 约 1 周 | 打开课程、观察、点选、讲解、步骤与重置 | 一节课可完整使用，内容和场景引用一致 |
| M2 核心教学交互 | 约 1–2 周 | 一项拆解/剖面/施工主题，必要的热点和引导 | 操作支持既定知识目标，暂停/回看/跳转一致 |
| M3 质量与首版发布 | 约 1 周 | 性能优化、异常处理、教学走查、兼容与发布 | 达到校准预算，关键缺陷关闭，可回滚 |
| M4 课程扩展 | 另行估算 | 更多桥型或知识点，可选理解检查 | 新内容主要由配置复用，复杂定制有明确价值 |

M0 若发现模型过重，先简化资产或首屏；若讲解目标不清，先调整课程脚本。两者都不应靠追加特效掩盖。

### 11.2 首批可直接建立的任务

1. 明确第一课目标与验收步骤，选择一个桥型和一项演示主题。
2. 制作程序化或轻量样例，建立构件 ID、名称、讲解和授权记录。
3. 验证兼容依赖、GLB 加载、目标浏览器、单位与相机。
4. 打通点选 → 构件 ID → 讲解与树联动 → 高亮与重置。
5. 建立课程步骤 Schema、直接跳转和可重放演示。
6. 检查快速切课、资源释放、加载失败与键盘操作。
7. 建立小型 E2E、内容校验与性能基线。
8. 完成一节课的知识审校和教学走查，再规划第二课。

### 11.3 完成定义 Definition of Done

- [ ] 学习目标与 Issue 验收步骤通过；功能对应明确的教学用途。
- [ ] 桥梁知识、图示和讲解经过适当审校，概念示意与简化条件清楚。

### 11.4 风险登记

| 风险 | 触发信号 | 应对与责任 |
| --- | --- | --- |
| 画面好看但学习目标不清 | 演示结束后说不清应掌握什么 | 教学负责人先明确目标，删减无关交互 |
| 示意造成知识误解 | 过度简化、夸张形变或工法被当作通则 | 知识审校人核对说明、范围和反馈 |
| 模型细节过多 | 关键构件难辨、弱设备加载慢 | 模型与开发负责人简化、分层和质量分级 |
| ID 或热点失配 | 优化后点错构件、标签漂移 | 自动映射校验及固定视角内容回归 |
| 输入方式排除部分学习者 | 只能拖拽、标签无法键盘访问 | 提供替代入口与可访问性测试 |
| 课程切换不稳定 | 旧模型回流、状态混合、内存持续增长 | 取消、版本校验和资源所有权检查 |
| 内容更新拖慢开发 | 每新增一课都要复制代码 | 稳定内容契约；高频能力配置化，特殊交互按需扩展 |
| 范围持续扩大 | 首版同时要求所有桥型及账号成绩系统 | 项目负责人保持首课闭环，扩展独立估算 |

## 12 参考资料

以下优先使用官方规范、官方文档和维护方源码。源码链接指向检索时使用的默认分支；实施时应记录所选依赖版本及对应 commit，以便复现。

1. [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html) 与 [WebGPURenderer](https://threejs.org/docs/pages/WebGPURenderer.html)：渲染器与平台要求。

4. [R3F 性能](https://r3f.docs.pmnd.rs/advanced/scaling-performance)、[常见陷阱](https://r3f.docs.pmnd.rs/advanced/pitfalls)、[事件](https://r3f.docs.pmnd.rs/api/events)、[测试](https://r3f.docs.pmnd.rs/api/testing)：React 与场景的协作边界。
5. [Three.js 资源清理](https://threejs.org/manual/pages/cleanup.html)：显式释放与共享资源。
6. [glTF Transform](https://gltf-transform.dev/)：可编程资产处理。
7. [Playwright 视觉快照](https://playwright.dev/docs/test-snapshots)：视觉回归与平台差异。
8. [That Open Components 许可证](https://github.com/ThatOpen/engine_components/blob/main/LICENSE.md)、[依赖清单](https://github.com/ThatOpen/engine_components/blob/main/packages/core/package.json)、[web-ifc 元数据](https://api.github.com/repos/ThatOpen/engine_web-ifc)：可选 IFC 资产链路的许可核对。

文中的教学功能、架构、预算、WBS 和流程是针对 3jsBridge 的实施建议，不是上游项目的保证。下一步应从 M0 的第一课脚本、轻量样例与目标设备验证开始。
